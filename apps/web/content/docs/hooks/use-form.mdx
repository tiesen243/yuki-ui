`useForm` is a lightweight typed form state manager built around Standard Schema validation. It keeps field values in a ref, exposes a render-prop `Field`, and coordinates validation, submission, reset, and pending state.

Unlike the Form Builder library, this hook is intentionally small and React-oriented. It is a good fit for regular DOM forms where you want schema validation without introducing a larger form abstraction.

## Usage

```tsx
import { useForm } from '@/hooks/use-form'
import * as z from 'zod'

const schema = z.object({
  email: z.string().email(),
})

export function LoginForm() {
  const form = useForm({
    defaultValues: { email: '' },
    schema,
    onSubmit: async (values) => {
      console.log(values)
    },
  })

  return (
    <form onSubmit={form.handleSubmit}>
      <form.Field
        name='email'
        render={({ field, meta }) => (
          <>
            <label htmlFor={field.id}>Email</label>
            <input {...field} />
            {meta.errors.map((error, index) => (
              <p key={index}>{error.message}</p>
            ))}
          </>
        )}
      />

      <button type='submit' disabled={form.state.isPending}>
        Submit
      </button>
    </form>
  )
}
```

## Validation

The `schema` option accepts either a Standard Schema implementation or a function returning a Standard Schema result.

Validation runs:

- before `onSubmit`,
- when a field loses focus after its value changed.

Field errors are filtered by the field name from the issue path.

## Field rendering

The render callback receives `field` and `meta`:

```ts
{
  field: {
    id: string
    name: TName
    value: TValues[TName]
    onChange: (valueOrEvent) => void
    onBlur: () => void
    form: string
    'aria-describedby': string
    'aria-invalid': boolean
  },
  meta: {
    descriptionId: string
    errorId: string
    errors: StandardSchemaV1.Issue[]
    isPending: boolean
  }
}
```

When passed a DOM change event, `onChange` maps checkboxes to booleans, number inputs to numbers, and other inputs to their string value.

## Submission lifecycle

`handleSubmit` prevents the browser default, validates the current values, invokes `onSubmit`, and then calls either `onSuccess` or `onError`.

The returned `state` exposes the latest form values, result data, error, and transition state.

## Reset

```tsx
form.reset()
```

Reset restores the original `defaultValues` and clears stored result/error state.

## API Reference

### `useForm`

```ts
useForm<TValues, TData, TError, TSchema, TResults>(options)
```

| Option          | Description                                                         |
| --------------- | ------------------------------------------------------------------- |
| `defaultValues` | Initial typed form values.                                          |
| `schema`        | Standard Schema or validation function.                             |
| `onSubmit`      | Callback receiving validated values. May return a value or Promise. |
| `onSuccess`     | Optional callback for successful submission.                        |
| `onError`       | Optional callback for validation/submission failures.               |

Returns:

| Property          | Description                                                 |
| ----------------- | ----------------------------------------------------------- |
| `formId`          | Stable form identifier used by generated accessibility IDs. |
| `Field`           | Generic field render-prop component.                        |
| `handleSubmit`    | Submit handler for the native form element.                 |
| `state.values`    | Current form values.                                        |
| `state.data`      | Last successful submission result.                          |
| `state.error`     | Last form error.                                            |
| `state.isPending` | React transition pending state.                             |
| `reset`           | Restores `defaultValues` and clears result/error state.     |
