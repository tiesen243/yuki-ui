The native `Toast` implementation provides an imperative notification API for React Native applications.

Unlike the web toast implementation, this component does not depend on Base UI. It maintains a small in-memory listener registry and renders notifications through `ToasterProvider`.

The system supports:

- Default notifications.
- Success, info, warning, and error variants.
- Optional descriptions.
- Custom icons.
- Configurable duration.
- Top or bottom positioning.
- Animated entry and exit.
- Horizontal swipe-to-dismiss gestures.

This is a native-specific component and does not have a direct shadcn/ui base component.

## Basic setup

Mount `ToasterProvider` near the root of the application.

```tsx
import { ToasterProvider } from '@/components/native/toast'

export function App() {
  return (
    <ToasterProvider>
      <Screen />
    </ToasterProvider>
  )
}
```

The provider renders your application and places the toast viewport above it.

## Usage

The global `toast` object exposes convenience methods.

```tsx
import { toast } from '@/components/native/toast'

toast.show('This is a simple notification.')
toast.success('Saved successfully!')
toast.info('Your account has been updated.')
toast.warning('This action may have side effects.')
toast.error('Something went wrong.')
```

Each method accepts:

```ts
toast.show(title, description?, options?)
toast.success(title, description?, options?)
toast.info(title, description?, options?)
toast.warning(title, description?, options?)
toast.error(title, description?, options?)
```

### Description

```tsx
toast.success(
  'Profile saved',
  'Your changes have been saved successfully.'
)
```

### Duration

The default duration is `3000ms`. Override it per toast.

```tsx
toast.show(
  'Long notification',
  'This notification stays visible longer.',
  { duration: 8000 }
)
```

### Custom icon

Pass an icon renderer through `options`.

```tsx
toast.show(
  'New message',
  'You have received a new message.',
  {
    icon: (props) => <MessageCircleIcon {...props} />,
  }
)
```

## Provider position

`ToasterProvider` supports `top` and `bottom`.

```tsx
<ToasterProvider position='top'>
  <App />
</ToasterProvider>
```

Or:

```tsx
<ToasterProvider position='bottom'>
  <App />
</ToasterProvider>
```

The viewport is positioned using absolute layout with horizontal insets.

## Swipe to dismiss

Toast cards can be swiped horizontally.

The gesture becomes active after horizontal movement exceeds the gesture threshold. Once the swipe passes roughly 40% of the toast width, the toast dismisses in the swipe direction.

If the swipe does not cross the threshold, the toast springs back to its original position.

Programmatic dismissal is handled by the provider after the exit animation completes.

## Animation lifecycle

When a toast appears:

1. It starts above or below its final position.
2. Its opacity starts at `0`.
3. It animates into place over `250ms`.
4. A timer is started using the configured duration.

When a toast is dismissed:

1. It translates vertically or horizontally depending on the dismissal reason.
2. Opacity animates to `0`.
3. The provider removes it from the active list.

## Toast variants

The built-in variants are:

- `default`
- `success`
- `info`
- `warning`
- `error`

Success, info, warning, and error variants use corresponding Lucide icons by default.

You can replace the icon by providing `options.icon`.

## Using `useToast`

`useToast` exposes the toast manager and the provider's dismiss function.

```tsx
import { useToast } from '@/components/native/toast'

function SaveButton() {
  const { toast } = useToast()

  return (
    <Button
      onPress={() => {
        toast.success('Saved')
      }}
    >
      Save
    </Button>
  )
}
```

`useToast` must be called underneath `ToasterProvider`.

## API reference

### `ToasterProvider`

```tsx
<ToasterProvider position='top'>
  {children}
</ToasterProvider>
```

| Prop | Default | Description |
| --- | --- | --- |
| `children` | — | Application content. |
| `position` | `top` | Toast viewport position: `top` or `bottom`. |

### `toast`

```ts
toast.show(title, description?, options?)
toast.success(title, description?, options?)
toast.info(title, description?, options?)
toast.warning(title, description?, options?)
toast.error(title, description?, options?)
```

### `ToastOptions`

```ts
interface ToastOptions {
  icon?: (props: LucidePropsWithClassName) => React.ReactNode
  duration?: number
}
```

### `useToast`

```ts
const { toast, dismiss } = useToast()
```

`dismiss` accepts the internal toast id. Most application code should use the convenience `toast` methods instead.

<Callout>

Mount exactly one `ToasterProvider` at the appropriate application root. Calling `toast.*` before a provider is mounted will not display a notification.

</Callout>
